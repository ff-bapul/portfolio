Overview

Terrascope's carbon management platform was originally built on Azure. As the product scaled to serve enterprise clients across APAC and Europe, the team identified significant opportunities to reduce costs, improve reliability, and leverage more mature cloud-native tooling by migrating to AWS.

I architected and led the full migration initiative — from designing the target AWS architecture, provisioning infrastructure via Terraform, containerizing services for EKS, and coordinating the phased cutover with zero business disruption.

Challenges & Solutions

🔴 Challenges

  • Live enterprise data with no acceptable downtime window
  • Stateful services tightly coupled to Azure-specific APIs
  • Existing manual infrastructure with no IaC baseline
  • Complex service mesh with ~20 microservices

🟢 Solutions

  • Blue-green deployment strategy with DNS-based traffic shifting
  • Abstracted Azure-specific dependencies behind interface adapters
  • Built entire AWS environment from scratch using Terraform modules
  • Migrated services incrementally with feature flags for rollback safety

Key Deliverables

  • Designed the target AWS architecture: EKS for container orchestration, RDS PostgreSQL for primary database, S3 + CloudFront for static assets, and ElastiCache Redis for caching.
  • Authored all Terraform modules for VPC, subnets, security groups, EKS cluster, IAM roles, and RDS — achieving full Infrastructure-as-Code reproducibility.
  • Set up ArgoCD for GitOps-based continuous deployment to EKS, replacing manual Azure DevOps pipelines.
  • Configured AWS CloudWatch + Grafana for unified observability across all services.
  • Implemented automated database migration scripts using Python + Alembic for schema and data migration with checksums.
  • Performed load testing post-migration to validate zero performance regression at 2× peak load.
