Overview

Terrascope's carbon accounting platform allows enterprises to track, calculate, and report Scope 1, 2, and 3 emissions. As client datasets grew into the hundreds of millions of rows, the existing Python-based recalculation engine became a critical bottleneck — full recalculations were taking 4–6 hours, blocking downstream reporting and compliance workflows.

I designed and implemented a new recalculation engine in Rust, leveraging its zero-cost abstractions and fearless concurrency model to achieve a 10× throughput improvement, reducing full recalculation time from hours to under 30 minutes.

Technical Design

  • Batch Processing: Jobs are divided into configurable batch sizes and processed using AWS Batch for highly scalable parallel execution.
  • Database I/O: Optimized PostgreSQL connection pooling and bulk COPY for high-throughput reads/writes.
  • Job Queue: Leveraged AWS Batch managed service for seamless job queueing and dispatch; results written back to S3 and PostgreSQL transactionally.
  • Emission Factors: Hot-loaded from a Redis cache with TTL-based invalidation to avoid repeated DB reads during batch runs.
  • Error Handling: Per-record error isolation — a single bad record doesn't abort the entire batch; failures logged and retried separately.
  • Containerized: Multi-stage Docker build producing a minimal ~12MB binary image deployed as AWS Batch jobs.

Challenges & Solutions

🔴 Challenges

  • Complex emission factor calculation logic ported from Python
  • Ensuring correctness at scale — numerical precision critical
  • Safe concurrent access to shared state across threads
  • Integration with existing Python-based platform services

🟢 Solutions

  • Property-based testing with Proptest; output cross-validated against Python reference
  • Used rust_decimal crate for arbitrary-precision arithmetic
  • Rust's memory safety guarantees prevented runtime crashes and ensured robust processing
  • Exposed results via shared PostgreSQL tables; backward-compatible API contract
