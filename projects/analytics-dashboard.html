Overview

At UST Global (Xpanxion), I led the development of an analytics dashboard platform for an energy management SaaS product. The platform needed to process and visualize large volumes of smart meter data, consumption trends, and anomaly reports for enterprise energy clients across multiple regions.

The key challenge was that the existing PostgreSQL-backed dashboards were painfully slow on large datasets. I introduced ClickHouse as an OLAP analytics store with AWS Batch for scheduled data aggregation jobs — dramatically improving query performance and enabling richer, real-time-feeling dashboards.

Architecture

  • Data Layer: Raw meter data in PostgreSQL → nightly AWS Batch jobs aggregate and transform data → loaded into ClickHouse materialized views for fast analytical queries.
  • Dashboard Layer: React + TypeScript frontend with Recharts and AG Grid for interactive charts, filterable tables, and exportable reports.
  • API Layer: Node.js / Express REST APIs serving pre-aggregated metrics from ClickHouse with Redis query caching for frequently accessed views.
  • Multi-tenant: Row-level security in ClickHouse + tenant-scoped API tokens ensuring complete data isolation across enterprise clients.
  • Design System: Built a reusable React component library (DLS) shared across 3 products — dashboard widgets, stepper workflows, data grids.

Challenges & Solutions

🔴 Challenges

  • PostgreSQL queries timing out on 100M+ row datasets
  • Dashboard inconsistency across different products
  • Complex filtering requiring sub-second response times
  • Large export files crashing browser on client side

🟢 Solutions

  • ClickHouse columnar storage + pre-computed materialized views
  • Unified Design Language System (DLS) with shared component library
  • Server-side filtering + pagination; Redis caching for hot queries
  • Streaming CSV export via chunked response — no client memory issues
