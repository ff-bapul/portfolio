Overview

Terrascope processes massive volumes of carbon emissions data from enterprise clients. Manual workflows for categorizing spend data, extracting insights from PDF reports, and generating compliance summaries were a significant bottleneck. I led the design and implementation of an AI-powered automation layer to address these challenges.

The system integrates OpenAI GPT-4 APIs with LangChain orchestration, a pgvector-backed retrieval layer, and custom agent chains to automate document understanding, data classification, and report generation workflows.

Architecture

  • Document Ingestion Layer: PDF/CSV upload → text extraction → chunking → embedding via OpenAI text-embedding-ada-002 → stored in pgvector (PostgreSQL).
  • RAG Pipeline: User queries trigger semantic search over the vector store, retrieving top-K relevant chunks, then passed to GPT-4 with a custom prompt template for grounded responses.
  • Agent Orchestration: LangChain agent chains coordinate multi-step tasks — e.g., classify emission source → lookup regulatory threshold → generate compliance note.
  • API Layer: FastAPI endpoints expose agent capabilities to the frontend with streaming responses via Server-Sent Events (SSE).
  • Observability: LangSmith for LLM trace logging and latency monitoring; custom dashboards in Grafana for token usage and cost tracking.

Challenges & Solutions

🔴 Challenges

  • Hallucination risk with ungrounded LLM responses on carbon data
  • High token costs at scale with enterprise-sized documents
  • Latency requirements for real-time user interactions
  • Ensuring data privacy — no enterprise data to external LLMs

🟢 Solutions

  • RAG with strict source citations and confidence scoring
  • Hierarchical chunking + summarization to reduce token footprint
  • Async processing + streaming responses for perceived speed
  • PII stripping pipeline before embedding; private VPC endpoints to OpenAI
